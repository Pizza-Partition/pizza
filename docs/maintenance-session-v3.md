# v3 同盘维护会话：实现与验收状态

更新：2026-10-27。本文件记录仓库中已实现和已验证的边界，不能视为 Linux／Windows 全流程已交付。

## 已实现的执行内核

`core/host/maintenance_compiler.zig` 在任何写入之前，以原设备的只读视图编译三份不可变程序：

1. **Bootstrap**：保留原分区身份，必要时通过原生文件系统规划器缩容，为盘尾临时分区腾出空间。
2. **Apply**：在保留临时分区的中间布局上执行已批准的用户意图。
3. **Cleanup**：明确接受后回收临时分区，得到用户批准的精确最终布局。

`program.Preview` 提供前一程序执行后的只读视图，后两份程序从该视图编译，不向原设备写入。
盘尾范围按恢复块对齐，允许 GPT 可用区末尾留下不足一个恢复块的间隙，兼容 512 字节扇区。
当前恢复区大小由调用者显式给出；空间不足则整个编译失败，尚未实现自动搜索最优恢复区大小。

临时区占用的原始有效数据也需要保留。缩容把文件搬离盘尾后，原来的分配记录可能仍会在撤销时恢复，
而临时日志会覆盖旧地址。因此 Bootstrap 通过公共文件系统分配接口查询原始有效范围，
在既有物理程序中加入这些范围的保留写入，使完整 before-image 在初始化盘尾日志之前进入 ESP 恢复容器。
容量预检包含这部分程序和恢复记录；不会把“文件已搬走”等同于“原地址可直接丢弃”。

`core/maint/storage/maintenance_session.zig` 将三个事务协调为持久状态机：

```text
prepared → bootstrapping → initialized → preparing_apply → applying → verified
                               ↓                              ↓
                       restoring_bootstrap ← undoing ←────────┘
                               ↓
                           rolled_back

verified → accepted → cleaning → committing_cleanup → completed
```

初始化或清理中断另有失败状态。恢复根据持久阶段完成回滚或提交，不重复执行原始请求。
`verified` 保留完整恢复数据；`accepted` 持久化后关闭撤销窗口。
清理中断回到清理前的已接受布局，并留在维护环境；当前没有自动重试清理的产品入口。

前置事务的写入范围会被后续事务合法复用。专用 `undoPredecessor` 只用于恢复前置事务，
仍校验程序、持久进度和每一份 before-image，允许当前写入范围已被后续日志使用。
普通恢复、用户计划接受及普通 Undo 的当前内容验证保持启用。

## 恢复容器与设备准入

- `RawCapsule` 在固定物理范围中预留记录容量，使用校验和及双份控制头；不会依赖可增长的稀疏日志。
- 会话另有两份控制块，绑定设备、会话和三份程序摘要。
- Bootstrap／Cleanup 的容器在 ESP，Apply 容器在临时盘尾区；容器之间及活动恢复区与目标写入之间必须隔离。
- ESP 整个范围受保护，只有已验证的恢复文件范围允许用于容器及控制块。
- `esp_anchor` 复用原生 FAT32 完整所有权扫描，验证文件路径、FAT 分配链、镜像、范围和非稀疏容量。
  维护期间文件内容可变，分配链必须冻结；不支持的文件布局会拒绝准入。
- 物理设备必须独占、未挂载，身份和几何必须匹配，恢复块不能小于物理扇区。
- 新增的同盘准入路径建立写入范围白名单。原有“独立恢复盘”路径仍保留其物理盘隔离检查。
- 初次准入读取 GPT 并确认 ESP。中断恢复允许 GPT 正处于撕裂状态，但要求可信原始 ESP 分配证据和有效会话控制头。

这些是底层接口。当前产品 helper 和 Web 服务没有暴露这条物理写入路径。

## 会话清单与固件启动租约

`session_manifest.zig` 将恢复证据、验证规则、原启动设置及三份程序放进一个有界二进制包。
包内不包含供高权限进程追随的程序路径。加载先验证包的原始字节摘要，再解析 JSON 和程序。

`boot_binding.zig` 在 Pizza 自有 UEFI 变量中绑定会话、设备、维护镜像和完整清单摘要。
已有不同或损坏绑定时拒绝覆盖。该机制提供相对于固件状态的完整性约束，不能替代 Secure Boot，
也不能抵抗另一个能够修改固件变量的高权限系统。

`uefi.Lease` 保存原 BootOrder／BootNext 和自有 Boot####，支持跨中断的安装及恢复。
维护事务活动期间 BootOrder 保留维护入口优先级，不单独依赖会被固件消费的 BootNext。
完成清理或完整撤销后，才允许恢复原启动设置并清除绑定；等待确认状态拒绝这一步。
遇到其他程序修改启动项时停止，不覆盖其内容。

`linux_efivars.zig` 提供固定 efivarfs 后端，每次变量写入使用一次 SetVariable 对应的 write，随后读回。
只对 Pizza 固定厂商变量处理 immutable 标志，不接受任意变量名称、GUID 或路径。
本轮验证使用内存固件后端，**没有修改开发主机的固件变量**。

生产准备器仍须负责：完整预分配 ESP 文件，持久化并读回启动租约／镜像／清单，验证镜像信任，
然后安装绑定、启用启动。首次启动离线重算与物理程序冻结之间的清单交接也尚未接通。
调用方传入的镜像摘要必须来自可信引导证据，不能接受 Web／命令行自称的摘要作为证明。

## 已运行的验收

```sh
zig build check test-host host-helper host-windows session-image
zig build test-storage-unit
zig build test-maint-session-image
```

在本地缓存只读的环境可设置 `ZIG_GLOBAL_CACHE_DIR=/tmp/pizza-zig-global`，不改变产品行为。

`test-host` 覆盖三阶段编译、512 字节尾部对齐、精确 GPT 最终布局、恢复文件证据、固件租约及清单完整性。
原生 FAT32 场景在实际盘尾放置文件分配块，缩容后覆盖旧地址，再分别验证 Undo 和接受后 Cleanup；
两条路径均扫描文件系统并检查文件内容和最终分区范围。

`test-storage-unit` 覆盖各持久化切点的掉电、撕裂、垃圾和重排模型，包括前置事务保护的地址被盘尾日志复用，
以及恢复重复调用的幂等性。该模型不等于真实固件／控制器断电验收。

`test-maint-session-image` 调用真实 `pizza-session-image` 子进程，使用临时普通文件依次执行编译、准备、
初始化、执行、重开、撤销／接受、清理，并比较 GPT 原始记录。它拒绝设备和符号链接。
该验收夹具的 ESP 是占位范围，原生 FAT32 分配证明由独立测试覆盖；夹具 JSON 清单不属于生产认证入口。

本轮确认通过：`check`、13 项 `test-host`、48 项 `test-storage-unit`、跨进程镜像验收，
以及 Linux helper、Windows 查询工具和镜像验收工具的编译。
`test-storage-crash -- --seed 20261027` 的 120 轮全套运行在 180 秒限制内未完成（退出码 124），不算通过。
全量 `test-filesystems` 尚未返回结果，`test-transition` 本轮未重跑。
