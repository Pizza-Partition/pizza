# 2026-10-24 正式物理入口 USB 验收

本次在用户明确授权后，通过正式 `pizza-maint` 验证物理设备获取、规划、执行、取消与恢复。程序自行打开目标，不接收实验监督器预先打开的设备句柄。使用当前工作树、Zig 0.17.0、Safe 模式，v7 物理程序与 v6 恢复协议。

## 设备与保护范围

仅操作 USB 序列号 `FC046CE92485C` 的既有分区 1，路径 `/dev/disk/by-id/usb-VendorC_ProductCode_FC046CE92485C-0:0-part1`，起点 `20,000,768 × 512`，容量 52,674,166,784 字节，逻辑扇区 512 字节。分区表和分区 2、3 不作为修改目标。原用户文件 12 个、7,818,790 字节，仍保存在宿主机与 USB 分区 3；每次操作前核对两份备份的逐文件 SHA-256。

生产查询获得稳定身份 `e46a3789f51363c6c632ebd4f5dcef48489608915ef538050b8fd85d9b8b8a43`。设备以独占直接 I/O 打开；恢复文件位于宿主机独立物理磁盘上的私有 Btrfs 目录。监督器只读挂载分区 3 核对备份，并独立检查设备序列号、分区范围及分区表。

## 发现并修复的准入问题

该 USB 桥的 SCSI VPD 属性文件存在，但读取返回 ENXIO。生产识别增加最近 USB 设备的厂商、产品、序列号、接口与 LUN 组合回退；缺失稳定序列号仍拒绝。单元夹具验证了这个回退及缺失身份时的拒绝。

首次已授权运行完成夹具布置后，在恢复目录准入时退出，没有创建事务记录或执行目标写入。原因是 Zig 非迭代目录使用 O_PATH 句柄，Btrfs FS_INFO ioctl 返回 EBADF。修复为从相同目录句柄重新打开可读目录后查询。监督器确认此前没有任何事务记录、全部有效基线未变，才继续相同夹具。

## 场景与结果

人工放置的 4 MiB 文件 `PIZZA.BIN` 位于分区内偏移 52,665,708,544 字节，清除原数据副本以强制缩容搬移。此步骤属于独立夹具准备，随后所有文件系统修改由正式程序执行。

| 场景                               | 结果                                           |
| ---------------------------------- | ---------------------------------------------- |
| 缩容在持久意图后收到 SIGINT        | 等待回滚完成，退出 130，持久 restored 标记存在 |
| SIGINT 后两次显式恢复              | 均返回已回滚；有效基线及文件一致               |
| 缩容在持久意图后 SIGKILL           | 进程退出 -9，下一进程读取持久记录恢复          |
| SIGKILL 后两次显式恢复             | 均返回已回滚；有效基线及文件一致               |
| 缩至 42,949,672,960 字节（40 GiB） | 455 步成功提交；独立检查和文件哈希通过         |
| 扩回 52,674,166,784 字节           | 199 步成功提交；独立检查和文件哈希通过         |
| 最终正式格式化，清除测试文件       | 197 步成功提交；独立检查为空 FAT32             |

两次回滚后通过直接 I/O 比较全部有效元数据和已分配簇，共 2 个连续范围、17,100,800 字节，逐字节一致。基线仅作为验收判据，不参与产品恢复。测试文件 SHA-256 始终为 `2f123cf664411a17345ffc8e055db6652774fd355f66ff6fdcbb3de16c73156d`。

`fsck.fat -n`、mtools 与直接 FAT 链检查通过。mtools 在调整前后提示既有 CHS 几何与 hidden sectors 不一致，但返回成功；本次不测试引导能力。
